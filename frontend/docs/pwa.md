# راهنمای جامع وب‌اپلیکیشن پیش‌رونده (PWA Guide)
## سامانه پاداش دانش‌آموزی (Student Reward System)

این مستند تشریح‌کننده معماری، پیکربندی، الزامات استقرار، و فرآیند اعتبارسنجی قابلیت نصب‌پذیری (Installability) وب‌اپلیکیشن پیش‌رونده (PWA) برای هر ۳ پنل کاربری سامانه می‌باشد:
1. **پنل دانش‌آموز (`@student-reward/student`)**
2. **پنل معلم (`@student-reward/teacher`)**
3. **پنل مدیریت سیستم (`@student-reward/admin`)**

---

## ۱. نحوه اجرا و توسعه (Development & Build)

### ۱.۱. اجرای پنل‌ها در محیط توسعه محلی (Dev Mode)
دستورات زیر از ریشه مخزن یا از پوشه `frontend` با `npm` اجرا می‌شوند:

```bash
# اجرای پنل دانش‌آموز (پورت 5173):
npm run dev:student

# اجرای پنل معلم (پورت 5174):
npm run dev:teacher

# اجرای پنل مدیریت (پورت 5175):
npm run dev:admin
```

> **نکته:** مرورگرها استاندارد PWA و Service Worker را روی مبدأ `localhost` بدون نیاز به گواهی HTTPS به رسمیت می‌شناسند.

### ۱.۲. کامپایل و بیلد نسخه پروداکشن (Production Build)
```bash
# بیلد تمامی پنل‌ها به صورت یکپارچه:
npm run build

# بیلد اختصاصی هر پنل:
npm run build:student
npm run build:teacher
npm run build:admin
```

### ۱.۳. ابزارهای کمکی PWA (تولید مجدد آیکون‌ها و تست صحت آرتفکت‌ها)
```bash
# تولید خودکار آیکون‌های استاندارد PWA با سایزهای ۱۹۲ و ۵۱۲ برای هر سه برنامه:
npm run generate:icons

# اعتبارسنجی خودکار مانیفست، ابعاد آیکون‌ها، تگ‌های HTML و سرویس‌ورکر در پوشه‌های dist:
npm run verify:pwa
```

| مشخصه | پنل دانش‌آموز (`student`) | پنل معلم (`teacher`) | پنل مدیریت (`admin`) |

## ۳. معماری سرویس‌ورکر و استراتژی کش (Service Worker & Caching)

پیاده‌سازی سرویس‌ورکر با استفاده از پلاگین استاندارد `vite-plugin-pwa` بر اساس نیازمندی‌های قطعی پروژه پیکربندی شده است:

1. **عدم کش داده‌های حساس و درخواست‌های API:**
   * درخواست‌های API تحت آدرس `/api/` و دامنه‌های خارجی مستثنی شده‌اند (`navigateFallbackDenylist: [/^\/api\//]`).
   * هیچ نشست، توکن یا اطلاعات هویتی کاربر در کش سرویس‌ورکر ذخیره نمی‌شود.
2. **کش بهینه App Shell:**
   * دارایی‌های استاتیک هش‌شده (`.js`, `.css`, فونت‌های وزیرمتن، آیکون‌ها) به عنوان پیش‌کش (Precache) ذخیره می‌شوند تا باز شدن پنجره Standalone فوری باشد.
3. **عدم مسدودسازی ناوبری با کش بی‌نهایت HTML:**
   * با استفاده از استراتژی `autoUpdate`، بررسی انتشار نسخه جدید در پس‌زمینه با هماهنگی Workbox انجام شده و کش‌های قدیمی پاکسازی می‌شوند (`cleanupOutdatedCaches: true`).
4. **جداسازی کامل از اپلیکیشن نیتیو اندروید (Capacitor Safe):**
   * در پنل دانش‌آموز، تابع `setupPwa()` وضعیت را با `Capacitor.isNativePlatform()` می‌سنجد. در صورتی که برنامه درون شل نیتیو اندروید در حال اجرا باشد، هیچ سرویس‌ورکری ثبت نمی‌شود تا از تداخل رفتاری در WebView نیتیو جلوگیری شود.

## ۴. الزامات استقرار و وب‌سرور پروداکشن (Production & HTTPS Requirements)

برای نصب موفقیت‌آمیز PWA در مرورگرها (مانند Google Chrome, Chromium Edge, Samsung Internet, Firefox Mobile):

1. **پروتکل امن HTTPS:**
   * ارائه دامنه با گواهی معتبر SSL/TLS (مانند Let's Encrypt) الزامی است. (مرورگرها نصب PWA را روی HTTP ناامن بلاک می‌کنند، به جز `localhost`).
2. **پشتیبانی از ناوبری SPA در وب‌سرور:**
   * وب‌سرور باید برای تمام روت‌ها فایل `index.html` را برگرداند.
3. **سیاست کش هدرهای HTTP در Nginx:**

```nginx
# نمونه پیکربندی بهینه برای Nginx:
server {
    listen 443 ssl http2;
    server_name student.yourdomain.ir;

    ssl_certificate /etc/letsencrypt/live/student.yourdomain.ir/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/student.yourdomain.ir/privkey.pem;

    root /var/www/student-reward/apps/student/dist;
    index index.html;

    # 1. روتینگ SPA
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 2. جلوگیری از کش طولانی‌مدت سرویس‌ورکر و مانیفست
    location ~* (sw\.js|manifest\.webmanifest)$ {
        add_header Cache-Control "no-cache, no-store, must-revalidate";
        add_header Pragma "no-cache";
        expires 0;
    }

    # 3. کش طولانی‌مدت دارایی‌های دارای هش یکتا
    location /assets/ {
        add_header Cache-Control "public, max-age=31536000, immutable";
    }

    # 4. سرو فایل نگارش اپلیکیشن بدون کش
    location = /app-version.json {
        add_header Cache-Control "no-cache, no-store, must-revalidate";
        add_header Pragma "no-cache";
        expires 0;
    }
}
```

## ۵. راهنمای تست و بررسی نصب‌پذیری (Verification Steps)

### ۵.۱. بررسی با Chrome DevTools (روی سیستم دسکتاپ)
1. برنامه مورد نظر را بیلد کرده و با `npm run preview` در ترمینال اجرا کنید:
   ```bash
   npm --prefix apps/student run preview -- --port 4173
   ```
2. مرورگر Google Chrome را باز کرده و به آدرس `http://localhost:4173` بروید.
3. کلید `F12` را زده و تب **Application** را انتخاب کنید.
4. بخش **Manifest**:
   * مطمئن شوید مقادیر Name، Short Name، Start URL، Theme Color، و Icons به درستی بارگذاری شده‌اند.
   * بر روی دکمه یا لینک **Installability** کلیک کنید و بررسی کنید هیچ خطایی نمایش داده نشود.
5. بخش **Service Workers**:
   * بررسی کنید سرویس‌ورکر وضعیت `Activated and is running` داشته باشد.
6. نوار آدرس مرورگر (Omnibox):
   * آیکون نصب برنامه (یک مانیتور با پیکان رو به پایین یا دکمه **Install**) در انتهای سمت راست نوار آدرس ظاهر خواهد شد. با کلیک بر روی آن، پنجره مستقل PWA نصب و باز می‌شود.

### ۵.۲. بررسی روی تلفن همراه (Android Chrome)
1. برنامه را روی سرور دارای HTTPS یا از طریق Remote Debugging / پورت محلی باز کنید.
2. بر روی منوی سه نقطه مرورگر کروم ضربه بزنید.
3. گزینه **"افزودن به صفحه اصلی"** یا **"نصب برنامه"** (Add to Home Screen / Install app) را انتخاب فرمایید.
4. نام و آیکون اختصاصی پنل ظاهر می‌شود؛ پس از تایید، آیکون برنامه در لانچر اندروید افزوده شده و با لمس آن، بدون نوار ابزار مرورگر و به صورت تمام‌صفحه باز خواهد شد.

### ۵.۳. بررسی چرخه حیات به‌روزرسانی (Update Lifecycle)
1. در حالی که برنامه در مرورگر یا پنجره PWA باز است، یک تغییر ظاهری کوچک ایجاد کرده و مجدداً بیلد بگیرید.
2. تب **Application > Service Workers** را مشاهده کنید. نگارش جدید سرویس‌ورکر دانلود شده و در پس‌زمینه اکتیو می‌شود.
3. بدون بستن یا کرش دادن فرم‌های کاربر، در ناوبری یا ریفرش بعدی کاربر، جدیدترین کدها در اختیار کاربر قرار می‌گیرند.

## ۶. محدودیت‌ها و نکات تکمیلی
* **iOS Safari:** مرورگر سافاری در iOS از پرامپت خودکار نصب پشتیبانی نمی‌کند؛ کاربران در سافاری می‌توانند از دکمه Share گزینه **"Add to Home Screen"** را انتخاب کنند. متاتگ‌های Apple Touch Icon و `apple-mobile-web-app-capable` در هر ۳ برنامه تعبیه شده‌اند.
* **شبیه‌ساز و دستگاه‌های آفلاین:** برنامه شل اولیه را بدون اینترنت اجرا می‌کند؛ اما از آنجا که کلیه داده‌ها متکی بر محاسبات آنلاین نوین و رول‌های احراز هویت هستند، پیام خطای اتصال سرور در صفحات مربوطه نمایش داده می‌شود.

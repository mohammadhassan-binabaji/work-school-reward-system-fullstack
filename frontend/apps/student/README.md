# سامانه پاداش دانش‌آموزی - پروژه اندروید (Capacitor)

این مستند راهنمای جامع راه‌اندازی، توسعه، همگام‌سازی و تولید خروجی اندروید (APK / AAB) برای اپلیکیشن دانش‌آموز با استفاده از **Capacitor 8** است.

---

## ۱. مشخصات پروژه اندروید

* **محیط فریم‌ورک وب:** Vue 3 + Vite + TypeScript + Pinia + Tailwind CSS
* **نسخه خازن (Capacitor):** `8.5.3` (شامل `@capacitor/core`، `@capacitor/android`، `@capacitor/cli` و افزونه `@capacitor/app@8.1.2`)
* **شناسه برنامه (Application ID / Package Name):** `ir.mhbj.student`
  > **نکته بسیار مهم:** شناسه برنامه (`appId`) شناسه یکتا و ثابت اپلیکیشن در پلتفرم اندروید و فروشگاه‌های نرم‌افزاری (کافه‌بازار، مایکت، گوگل پلی) است. تغییر این شناسه پس از انتشار عمومی، امکان به‌روزرسانی نسخه‌های قبلی کاربران را از بین برده و برنامه به عنوان یک اپلیکیشن کاملاً مجزا شناخته خواهد شد.
* **نام نمایشی برنامه (App Name):** `ناصر نوین`
* **مسیر پروژه نیتیو اندروید:** `frontend/apps/student/android`
* **پوشه بیلد وب (Web Directory):** `frontend/apps/student/dist`

---

## ۲. پیش‌نیازها و نسخه‌های ابزارها

برای ساخت و اجرای پروژه در اندروید، ابزارهای زیر مورد نیاز است:

1. **Node.js:** نسخه `22` یا بالاتر (در این مخزن نسخه `v24.18.1` و `npm 12.0.2` استفاده شده است).
2. **Java Development Kit (JDK):** نسخه `JDK 17` یا `JDK 21` (نسخه پیشنهادی برای Android Gradle Plugin 8.x و Capacitor 8). متغیر محیطی `JAVA_HOME` باید به درستی تنظیم شده باشد.
3. **Android Studio:** نسخه پایدار (Ladybug، Koala، یا جدیدتر).
4. **Android SDK:**
   * `compileSdkVersion`: **36**
   * `targetSdkVersion`: **36**
   * `minSdkVersion`: **24** (اندروید 7.0 و بالاتر)

## ۳. دستورات کاری و اسکریپت‌ها

تمامی دستورات از ریشه مونو‌ریپو یا از داخل پوشه `frontend` با استفاده از npm قابل اجرا هستند:

### ۳.۱. نصب وابستگی‌ها
```bash
# از ریشه مخزن:
npm --prefix frontend install
```

### ۳.۲. اجرای تست‌های یونیت
```bash
# اجرای تست‌های سرویس نسخه و مقایسه معنایی:
npm --prefix frontend run test:student
```

### ۳.۳. بیلد پروداکشن وب و همگام‌سازی با اندروید
```bash
# کامپایل فرانت‌اند دانش‌آموز:
npm --prefix frontend run build:student

# همگام‌سازی است‌های وب و پلاگین‌ها با پروژه اندروید:
npm --prefix frontend run cap:sync:student

# یا اجرای همزمان بیلد و همگام‌سازی:
npm --prefix frontend run cap:build:student
```

### ۳.۴. باز کردن پروژه در Android Studio
```bash
npm --prefix frontend run cap:open:student
```
یا می‌توانید به صورت دستی نرم‌افزار **Android Studio** را باز کرده و پوشه `frontend/apps/student/android` را انتخاب (Open) کنید.

## ۴. پیکربندی شبکه و آدرس API (توسعه در برابر تولید)

کلاینت متمرکز HTTP (`ApiClient`) و سرویس نسخه از متغیرهای محیطی استاندارد Vite استفاده می‌کنند.

### ۴.۱. محیط توسعه محلی (Local Development)
در فایل `.env.example`:
* **در مرورگر وب سیستم:** `VITE_API_BASE_URL=http://localhost:3000/api/v1`
* **در شبیه‌ساز اندروید (Android Emulator):** آدرس `localhost` در شبیه‌ساز به خود دستگاه مجازی اشاره دارد، نه سیستم میزبان شما. برای اتصال از شبیه‌ساز به سرور بک‌اند در پورت ۳۰۰۰ سیستم میزبان، از آدرس آی‌پی روتر مجازی اندروید استفاده کنید:
  ```env
  VITE_API_BASE_URL=http://10.0.2.2:3000/api/v1
  ```
* **در دستگاه واقعی (Physical Device via Wi-Fi):** از آی‌پی شبکه محلی سیستم (مانند `http://192.168.1.50:3000/api/v1`) استفاده فرمایید.

### ۴.۲. محیط تولید واقعی (Production)
برای بیلد نهایی اپلیکیشن:
1. فایل `frontend/apps/student/.env.production.example` را کپی کرده و به نام `.env.production` ذخیره نمایید.
2. آدرس واقعی با پروتکل امن **HTTPS** را وارد کنید:
   ```env
   VITE_API_BASE_URL=https://api.mhbj.ir/api/v1
   VITE_APP_VERSION_URL=https://student.mhbj.ir/app-version.json
   ```
> **هشدار امنیتی:** پروتکل HTTP بدون رمزنگاری (Cleartext HTTP) در نسخه‌های پروداکشن اندروید به صورت پیش‌فرض توسط سیستم‌عامل مسدود می‌شود. از آدرس‌های `localhost` یا پروتکل‌های ناامن در پروداکشن استفاده نکنید. همچنین کلیدهای محرمانه نباید در متغیرهای فرانت‌اند قرار گیرند، زیرا در خروجی برنامه کامپایل می‌شوند.

## ۵. سیستم مدیریت نسخه و به‌روزرسانی اجباری (Force Update)

بررسی نسخه اپلیکیشن از طریق فایل استاتیک `app-version.json` که روی مبدأ وب فرانت‌اند دانش‌آموز قرار دارد، انجام می‌شود (بدون نیاز به تغییر اندپوینت‌های بک‌اند NestJS).

### ۵.۱. ساختار فایل `app-version.json`
این فایل در مسیر `frontend/apps/student/public/app-version.json` قرار دارد و با بیلد وب در ریشه خروجی کپی می‌شود:
```json
{
  "platform": "android",
  "latestVersion": "1.0.0",
  "minimumVersion": "1.0.0",
  "updateUrl": "https://yourdomain.com/download/student-app.apk",
  "message": "نسخه جدید سامانه پاداش دانش‌آموزی در دسترس است. لطفاً برنامه را به‌روزرسانی کنید."
}
```

### ۵.۲. تفاوت `versionName` و `versionCode`
در فایل `frontend/apps/student/android/app/build.gradle`:
* **`versionName`:** رشته نگارش خوانا برای کاربر منطبق بر قرارداد معنایی SemVer (مانند `1.0.0` یا `1.1.0`).
* **`versionCode`:** عدد صحیح صعودی و یکتا (مانند `1`, `2`, `3`). هر بار که نسخه جدیدی برای انتشار به کافه‌بازار، مایکت یا به صورت مستقیم آماده می‌کنید، این عدد باید افزایش یابد تا اندروید اجازه جایگزینی بسته را بدهد.

### ۵.۳. رفتار سیستم در اپلیکیشن
* **به‌روزرسانی اجباری (`FORCE_UPDATE`):** اگر `installedVersion < minimumVersion` باشد، یک صفحه تمام‌صفحه مسدودکننده (Blocking) راست‌چین با تم تاریک نمایش داده می‌شود و دکمه دانلود نسخه جدید فعال است. فشردن دکمه بازگشت (Back) در اندروید به جای دور زدن صفحه، برنامه را می‌بندد.
* **به‌روزرسانی اختیاری (`OPTIONAL_UPDATE`):** اگر نسخه کاربر کمتر از آخرین نسخه باشد ولی به حداقل نسخه رسیده باشد، یک پیام شناور غیرمسدودکننده نمایش داده می‌شود که دکمه «بعداً» جهت بستن پیام دارد.
* **خطای شبکه یا قطعی اینترنت:** یک اعلان عدم دسترسی با دکمه «تلاش مجدد» نمایش داده شده و مانع از ورود کاربر در شرایط عدم دسترسی موقت نمی‌شود.

### ۵.۴. پیکربندی وب‌سرور Nginx برای فایل نسخه
برای جلوگیری از کش شدن طولانی‌مدت فایل نسخه در مرورگرها و کلاینت‌ها، در تنظیمات Nginx مبدأ وب دانش‌آموز هدرهای زیر توصیه می‌شود:
```nginx
location = /app-version.json {
    add_header Cache-Control "no-cache, no-store, must-revalidate";
    add_header Pragma "no-cache";
    expires 0;
}
```

### ۵.۵. مرز امنیتی
بررسی کلاینت‌ساید نسخه یک ابزار مدیریت تجربه کاربری و هماهنگی انتشار است و مرز امنیتی محسوب نمی‌شود. در صورتی که به دلایل امنیتی یا تغییر ساختار پایگاه داده نیاز به مسدودسازی کامل نسخه‌های قدیمی باشد، اعمال این محدودیت باید در سطح بک‌اند (بررسی هدر نسخه ارسالی) انجام پذیرد.

## ۶. ناوبری و کلید بازگشت فیزیکی اندروید (Hardware Back Button)

با ادغام پلاگین `@capacitor/app` و ماژول `mobileNavigation`:
1. در صورتی که باتم‌شیت (مانند جزئیات چالش، ارسال مدارک یا جزئیات پاداش) باز باشد، اولین فشردن کلید بازگشت، باتم‌شیت را می‌بندد.
2. در صفحات فرعی برنامه (مانند `/challenges`, `/rewards`, `/notifications`)، فشردن کلید بازگشت به صفحه قبلی بازمی‌گردد.
3. در صفحه اصلی (داشبورد `/` یا صفحه ورود `/login`)، فشردن کلید بازگشت برنامه را به آرامی می‌بندد و از افتادن در حلقه ناوبری جلوگیری می‌کند.

## ۷. مراحل بیلد و تولید خروجی نهایی (APK / AAB) در Android Studio

پس از اجرای `npm --prefix frontend run cap:build:student`:

1. پروژه را در **Android Studio** باز کنید (`npm --prefix frontend run cap:open:student`).
2. صبر کنید تا Gradle فرآیند ایندکس و سینک را به پایان برساند.
3. **تست روی شبیه‌ساز یا دستگاه متصل:**
   * دستگاه فیزیکی یا امولاتور مورد نظر را از نوار ابزار بالا انتخاب کنید.
   * دکمه **Run 'app'** (آیکون مثلث سبز یا کلید میانبر `Shift + F10`) را بزنید.
4. **تولید خروجی دستی برای انتشار (Signed APK / AAB):**
   * از منوی بالا به مسیر **Build > Generate Signed Bundle / APK...** بروید.
   * گزینه **Android App Bundle** (برای گوگل پلی) یا **APK** (برای کافه‌بازار، مایکت یا نصب مستقیم) را انتخاب کنید.
   * فایل کلید امضا (Keystore) خود را انتخاب کرده یا با زدن **Create new...** یک کلید امضای معتبر جدید بسازید. (کلید امضا و کلمه عبور را در جای امن نگهداری کنید و هرگز در گیت کامیت نکنید).
   * نوع بیلد (Build Variant) را روی **release** قرار دهید.
   * هر دو گزینه **V1 (Jar Signature)** و **V2 (Full APK Signature)** را تیک بزنید.
   * دکمه **Finish** را بزنید تا خروجی نهایی تولید شود. فایل‌های کامپایل‌شده در مسیر `android/app/release/` قرار خواهند گرفت.
